Scheduler: Window State Machine

The scheduler polls the Anthropic usage API every poll_interval (default 180s) and feeds each snapshot into a finite state machine that tracks the 5-hour session window:

IDLE
→
OPEN
→
SATURATED
→
DRAINING
↻
OPEN
StateConditionBehavior
IDLE No usage data yet / no active window Waiting for first API response
OPEN Active window, util < threshold Launches eligible tasks (up to parallel_n)
SATURATED util ≥ util_threshold No new launches; in-flight runs continue
DRAINING Time to reset < min_launch_window (20m) No new launches; runs SIGTERM before window closes

Reset detection: either resets_at advances by >2m or utilization drops >40 pts (catches missed resets during laptop sleep). On reset, state returns to OPEN.

Scheduler: Evaluate Loop

Each tick, after observing the window, the scheduler runs evaluate():

per tick:
  fetch usage snapshot → store + SSE broadcast
  window.Observe(snapshot)     → update FSM state, detect resets
  reconcile()                  → adopt orphaned runs or mark dead
  evaluate()                   → gate checks → candidate selection → launch

evaluate():
  if running >= parallel_n              → stop
  if 5h util >= util_threshold          → stop  (SATURATED)
  if 7-day util >= 95%                  → backoff until 7-day resets_at
  if time_to_reset < min_launch_window  → stop  (DRAINING)

  candidates = resumable_runs (resume-first!) ++ queued_tasks_by_order

  for each candidate while running < parallel_n:
    estimate = size_estimates[task.size]   // {duration, budget, timeout, util_cost}
    will_finish = estimate.duration * 1.25 ≤ time_to_reset
    timeout     = min(estimate.max_timeout, time_to_reset − drain_margin)

    if will_finish → launch(task, timeout)

Runner: Worktree + Resume Lifecycle

New Task Launch

  1. Detect default branch (git rev-parse --abbrev-ref origin/HEAD)
  2. git worktree add ~/.burnrate/worktrees/task-<id> -b burnrate/<id>-<slug>
  3. Persist worktree_path, branch, repo_path to the run row before invoking claude
  4. Build prompt from worker-new.md template + task data + runtime context
  5. Invoke: claude --print --output-format stream-json --verbose --dangerously-skip-permissions --model <model> --max-budget-usd <budget> -p "<prompt>"
  6. Session ID persisted early via OnSessionID callback (parsed from system/init event)
  7. On success: extract PR URL from output, mark task done, remove worktree

Resume Flow (HR2: Resume, Never Restart)

  1. Interrupted runs (rate limit, timeout, crash) keep their worktree + session ID
  2. Task marked resumable — resumable runs have priority over queued tasks
  3. Next window: claude --resume <session_id> in the same worktree
  4. Prompt switches to worker-resume.md: "check git status + git log, continue where you left off"
  5. Session IDs chain across attempts — no tokens wasted redoing work

Usage Polling

GET https://api.anthropic.com/api/oauth/usage

Headers:
  Authorization: Bearer <oauth_access_token>
  anthropic-beta: oauth-2025-04-20
  User-Agent: claude-code/<version>    ← required or instant 429

Response:
  { five_hour:  { utilization: 0-100, resets_at: ISO8601 },
    seven_day:  { utilization, resets_at },
    seven_day_opus, seven_day_sonnet, scoped_weekly, extra_usage }

Token source: macOS Keychain (Claude Code-credentials) → JSON → claudeAiOauth.accessToken. Refreshed automatically when near-expiry. Pinned accounts resolve via sandbox keychain paths. Snapshots stored in usage_snapshots table, trimmed after 14 days.

Process Model

launchd (com.burnrate.agent, KeepAlive=true)
  └─ burnrate serve
       ├─ scheduler goroutine (poll loop every 180s)
       │    ├─ usage.Client.Fetch() → Anthropic API
       │    ├─ window.Observe()     → FSM transition
       │    ├─ reconcile()          → adopt/kill orphaned pids
       │    └─ evaluate()           → launch up to parallel_n tasks
       │         └─ runner.Run() goroutine (per task)
       │              ├─ git worktree add
       │              ├─ claude -p --output-format stream-json
       │              │    (own process group, SIGTERM+5s→SIGKILL on timeout)
       │              ├─ stream → log file + session_id extraction
       │              └─ classify → done|resumable|failed + cleanup
       └─ HTTP server goroutine
            ├─ REST API handlers
            ├─ SSE hub (broadcast on usage/run/task events)
            └─ static file server (embedded web UI)

Key Design Decisions

Resume, Never Restart

Session IDs are captured early (from the first system/init event) and persisted before any work happens. Interrupted runs always resume with --resume in the same worktree — no tokens wasted.

Daemon-Owned Worktrees

Git worktrees are created by the Go daemon (not the agent), so paths are known for resume, cleanup, and recovery. The agent works inside a pre-created worktree.

Catch-Up, Not Timers

Window resets are detected by comparing resets_at and utilization drops on each poll tick. No timer needs to fire at the exact reset instant — laptop sleep is handled by catch-up.

Finish-Within-Session

Tasks are only launched if their size estimate says they'll finish before the window closes. Per-run timeout = min(max_timeout, time_to_reset − drain_margin), ensuring graceful SIGTERM before the API starts rejecting.
